02 Focus

Release integrity for autonomous change

Coding agents increase the rate of change. They do not establish what is deployed, which build contains a fix, or whether policy allowed the promotion. Those facts have to come from the release record.

  1. 01

    Distributed caching

    Services and concurrent agents depend on a shared cache that remains correct under load.

  2. 02

    SDLC protection

    Controls run from build through promotion. A finding reported after release does not protect the artifact that already shipped.

  3. 03

    Standardization

    A release has one identity. Engineers and agents refer to the same binary, package, and environment.

  4. 04

    Governance

    Promotion policy is executable. An agent that can publish a package is subject to a rule that can deny it, with the decision retained.

03 Capabilities

Access, evaluation, and admission

Production use of agents requires a defined tool protocol, retrieval over authoritative data, evaluation of outputs, and authentication of the workload before it is allowed to act.

  1. 01

    Agentic DevOps

    Autonomous workflows for code review, security scanning, and pipeline governance across the software development lifecycle.

  2. 02

    Agentic programming

    Multi-agent systems for code generation and debugging, with an explicit contract between each step.

  3. 03

    Model Context Protocol

    Production MCP servers that connect models to internal tools and data sources. Authorization is enforced outside the prompt.

  4. 04

    Retrieval-augmented generation

    Retrieval over repository metadata and internal documentation, indexed in Azure Vector DB. Responses retain the source they were drawn from.

  5. 05

    Prompt engineering

    Prompts are versioned and reviewed. A change in wording is treated as a change in system behavior.

  6. 06

    Multi-agent orchestration

    Coordination of specialized agents: which context each one receives, and the point at which policy resumes control.

  7. 07

    LangSmith

    Tracing and evaluation of agent chains, including prompt version, tool calls, and whether the output met its contract.

  8. 08

    Custom AI testing frameworks

    A test framework for agent behavior: fixtures, expected tool calls, and deterministic checks, executed as part of the pipeline.

  9. 09

    Agentic gateway

    Authentication and authorization for agent workloads using SPIFFE. The workload presents a SPIFFE ID and a short-lived SVID. The gateway authorizes tools, data, and environments, and records the decision.

05 Practice

Engineering practice

Resolve intent to a build.

A version label identifies an artifact. An instruction such as “deploy the build that fixed checkout” identifies intent. The platform should resolve one to the other.

Attach evidence to the release.

Pull requests, commits, and change summaries travel with the release, so deployment status can be reported from the record.

Constrain autonomy with policy.

Caching, contracts, and executable policy keep autonomous workflows operable. An answer that was not checked is a defect.
